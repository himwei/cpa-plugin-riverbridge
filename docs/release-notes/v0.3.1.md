## RiverBridge 0.3.1

把 [River AI](https://docs.river.ai) 接入 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) 的 CPA 插件：
配置一次 River API Key，模型即可以 `river-` 前缀进入 `/v1/models`，并附带一个由 CPA 自己托管的网页控制台。

首个正式发布版本。制品是 **FreeBSD 14.3 / amd64** 的 C 共享库，由 GitHub Actions 在 FreeBSD 虚拟机里编译
（go1.26.10，`-trimpath -buildvcs=false -ldflags='-s -w'`）。

### 下载

| 文件 | 说明 |
| --- | --- |
| `riverbridge-0.3.1.so` | 插件本体，放到 `plugins/freebsd/amd64/riverbridge.so` |
| `checksums.txt` | sha256 校验和 |

```sh
curl -LO https://github.com/himwei/cpa-plugin-riverbridge/releases/download/v0.3.1/riverbridge-0.3.1.so
curl -LO https://github.com/himwei/cpa-plugin-riverbridge/releases/download/v0.3.1/checksums.txt
sha256 -q riverbridge-0.3.1.so    # 与 checksums.txt 比对
```

装好后在 `config.yaml` 启用，重启 CPA，看到这行即成功：

```
pluginhost: plugin registered plugin_id=riverbridge plugin_name=RiverBridge version=0.3.1
```

### 功能

- **一次配置** —— 粘贴 `rv_...` Key，**先向上游探活再落盘**，废 key 不会进 auth 目录
- **`river-` 前缀** —— 去掉厂商段后加前缀，回程反向映射，River 收到的永远是原始模型 id
- **四标签页控制台** —— 日志 / 账号配置 / 路由策略 / 设置概览，入口
  `/v0/resource/plugins/riverbridge/console`
- **消费上限** —— River 没有余额接口，改为每把 key 一个美元上限（设 `0` 不限）。
  累计值存在 `spend.json` 而**不是** auth 文件：CPA 每次请求都会重建 auth 记录，
  存那里的计数器会在计费后一秒内被清零
- **日志** —— 落盘、保留 50–10000 行（默认 1000），支持 NDJSON 导出；
  默认打开「今天」+「仅请求」，不会被重启时的系统事件淹没
- **路由** —— fill-first / round-robin + 失败重试；实现 `scheduler.pick`，
  路由页显示实时 pick 计数，能看出到底是谁在挑
- **流式代理** —— 逐帧转发不做缓冲，5 分钟无帧自动中断，避免死上游占住连接
- **用量估算** —— River 流式从不报 usage，按 3 字符/token 折算并标 `estimated`
  （同一 prompt 实测 25/156 token，估算 22/150）
- **计价表** —— 内置费率，控制台不额外发 API 调用就能显示花费

### 已知限制

- 假设**单运维者**：无多租户、无 RBAC，控制台凭 CPA 管理密钥鉴权
- `scheduler.pick` CPA 只认**第一个**声明的插件，且按文件名顺序加载；
  若被别的插件抢占，你选的策略会回落到 CPA 内置行为（不报错，路由页计数能看出来）
- 同时跑 `cpa-key-billing` 时，新增模型需手动注册价目，
  否则该插件会以 `model_price_error`（HTTP 503）拒绝请求
